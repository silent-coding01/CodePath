1. Introduction to Recursion

Recursion is a programming technique in which a function calls itself to solve a smaller version of the same problem.

Here is a simple example:

#include <stdio.h>

void countDown(int n)
{
    if (n == 0)
        return;

    printf("%d\n", n);
    countDown(n - 1);
}

int main(void)
{
    countDown(5);

    return 0;
}

Output:

5
4
3
2
1

When countDown(5) runs, it prints 5 and calls countDown(4). This continues until the function receives 0 and returns.

Key idea: A recursive function solves a problem by working on a smaller input until it reaches a stopping condition.

2. Base Case and Recursive Case

A recursive function usually needs two important parts.

Base case

The base case stops the recursion. Without a reachable stopping condition, recursive calls may continue until the program runs out of stack space.

Recursive case

The recursive case calls the same function with an input that moves toward the base case. 

void printNumbers(int n)
{
    if (n == 0)        // Base case
        return;

    printf("%d ", n);
    printNumbers(n - 1);  // Recursive case
}
Ask yourself two questions when writing recursion:
  1. When should the function stop?
  2. How will each call move closer to stopping?

3. Print Numbers Using Recursion

Let's print numbers from 1 to n.

#include <stdio.h>

void printNumbers(int n)
{
    if (n == 0)
        return;

    printNumbers(n - 1);
    printf("%d ", n);
}

int main(void)
{
    printNumbers(5);

    return 0;
}

Output:

1 2 3 4 5

Notice that the recursive call happens before printf(). The function calls descend toward zero first, then print while the calls return.

If printf() is placed before the recursive call, the output will instead be 5 4 3 2 1.

4. Sum of Natural Numbers

We can define the sum recursively:

sum(n) = n + sum(n - 1)

For the base case, sum(0) = 0.

#include <stdio.h>

int sum(int n)
{
    if (n == 0)
        return 0;

    return n + sum(n - 1);
}

int main(void)
{
    printf("Sum = %d\n", sum(5));

    return 0;
}

Output:

Sum = 15

The calculation expands like this:

sum(5)
= 5 + sum(4)
= 5 + 4 + sum(3)
= 5 + 4 + 3 + sum(2)
= 5 + 4 + 3 + 2 + sum(1)
= 5 + 4 + 3 + 2 + 1 + sum(0)
= 15

5. Factorial Using Recursion

The factorial of a positive integer n is the product of all integers from 1 to n.

5! = 5 × 4 × 3 × 2 × 1 = 120

Mathematically:

  • factorial(0) = 1
  • factorial(n) = n × factorial(n - 1) for n > 0
#include <stdio.h>

unsigned long long factorial(int n)
{
    if (n == 0)
        return 1;

    return (unsigned long long)n * factorial(n - 1);
}

int main(void)
{
    int n = 5;

    printf("Factorial = %llu\n", factorial(n));

    return 0;
}

Output:

Factorial = 120
This example assumes a non-negative input. A production program should validate the input and prevent values that overflow the chosen integer type. In this example, 20! fits in a typical 64-bit unsigned long long.

6. Understanding the Call Stack

Every active function call needs space to keep track of its local state and where execution should resume. Recursive calls create multiple active calls.

Consider this function:

void show(int n)
{
    if (n == 0)
        return;

    printf("%d ", n);
    show(n - 1);
    printf("%d ", n);
}

Calling show(3) produces:

3 2 1 1 2 3

The first print happens as calls descend. The second print happens as those calls return.

Trace carefully: Write down what happens before the recursive call and what happens after it returns.

7. Fibonacci Series

In the Fibonacci sequence, each term after the first two is the sum of the previous two terms.

0, 1, 1, 2, 3, 5, 8, 13, ...

#include <stdio.h>

int fibonacci(int n)
{
    if (n == 0)
        return 0;

    if (n == 1)
        return 1;

    return fibonacci(n - 1) + fibonacci(n - 2);
}

int main(void)
{
    int i;

    for (i = 0; i < 8; i++)
    {
        printf("%d ", fibonacci(i));
    }

    printf("\n");

    return 0;
}

Output:

0 1 1 2 3 5 8 13
This simple recursive implementation repeats many calculations. It is useful for learning recursion, but it becomes slow for larger inputs. Iteration or memoization is more efficient for larger sequences.

8. Sum of Digits Using Recursion

We can find the sum of a non-negative integer's digits by adding its last digit to the sum of the remaining digits.

sumDigits(n) = n % 10 + sumDigits(n / 10)

#include <stdio.h>

int sumDigits(int n)
{
    if (n == 0)
        return 0;

    return n % 10 + sumDigits(n / 10);
}

int main(void)
{
    printf("Sum = %d\n", sumDigits(1234));

    return 0;
}

Output:

Sum = 10

The calculation is 4 + 3 + 2 + 1 = 10. This example assumes a non-negative integer.

9. Reverse a Number Using Recursion

A recursive function can also build a reversed number by carrying the result accumulated so far. 

#include <stdio.h>

int reverseNumber(int n, int reversed)
{
    if (n == 0)
        return reversed;

    return reverseNumber(n / 10, reversed * 10 + n % 10);
}

int main(void)
{
    int n = 1234;

    printf("Reverse = %d\n", reverseNumber(n, 0));

    return 0;
}

Output:

Reverse = 4321
This example assumes a non-negative input and does not preserve leading zeros. For example, reversing 120 produces 21 as an integer.

10. Recursion vs Loops

  • Loops: Repeat instructions using constructs such as for and while.
  • Recursion: Solves a problem through function calls on smaller inputs.
  • Memory: Recursive calls use call-stack space.
  • Readability: Recursion can make some problems easier to express, but not every problem benefits from it.
  • Performance: A loop may be simpler and more efficient for straightforward repetition.
Recursion is especially useful for understanding problems that naturally break into smaller versions of themselves. It is not automatically better than a loop.

11. Common Mistakes

Mistake 1: Forgetting the base case

Without a stopping condition, recursive calls can continue until the program runs out of stack space.

Mistake 2: Not moving toward the base case

If the input never gets closer to the stopping condition, recursion may not terminate.

Mistake 3: Confusing the order of statements

Statements before the recursive call execute while calls descend. Statements after it execute as calls return.

Mistake 4: Ignoring input limits

Deep recursion can exhaust the stack, and mathematical results can overflow integer types. Choose appropriate input limits.
